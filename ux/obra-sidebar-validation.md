# Native Obra sidebar validation — 2026-10-08

The sidebar is now a self-contained built-in extension generated by
`@obra/workbench-ui` into `vscode/extensions/obra-workbench-ui`. The previous
stylesheet, core contribution, workbench import and core localization entry are
removed. Work remains on the existing `feat/obra-sidebar` branches; `main` and
the canonical upstream baseline have not been changed. This is an experimental
UI-only implementation. Human visual approval remains pending.

Normal startup shows five empty native views. Sample data requires **Obra:
Mostrar proyecto de ejemplo**. The project tree follows Storybook's
`EXPLORER_ITEMS`, including every label, child order and document icon. Sample
documents use a native read-only `obra-sample:` text provider and create no
project files. **Obra: Salir de vista previa**, reload, and disabling
`obra.sidebar.enabled` reset the navigation. Re-enabling restores empty views.
The extension-owned onboarding marker opens Proyectos once in an empty window;
reload preserves the user's subsequently selected view.

The native runner launches ordinary `scripts/code.sh` with a clean temporary
profile and **no extension-development flag**. It uses
`VSCODE_SKIP_PRELAUNCH=1` with the existing client/Electron build. This avoids
writing the shared `~/.vscode-oss-dev/extensions/control.json`; prelaunch itself
encountered a sandbox permission error on that file. Native extension discovery
uses the normal built-in scanner, independently of this cache/prelaunch step.
The runner verifies all five icons and welcome states, explicit preview
activation, text editor rejection of typed edits, native arrow-key expansion,
preview exit, reload/reset with Inbox still selected, all-container off/on,
and the upstream native Explorer command. Modern UI is exercised on the native
high-contrast light theme. Temporary profiles are removed after verification.

The packaging check verifies the extension matches the fork's normal local
built-in packaging glob and exclusions, uses the same `vsce.listFiles` file
selection as `fromLocalNormal`, builds a VSIX, and inspects its archive. A full
platform distribution build was not run.

The captures use native headings and controls throughout. The normal heading
uses VS Code's uppercase/truncation treatment; Modern UI applies its own title
styling. No package stylesheet overrides either behavior. Capture review:
